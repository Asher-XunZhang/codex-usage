# macOS v1.0.3.post2：额度认证恢复

本版修复账号认证被拒绝后，反复刷新仍停留在旧额度的路径。发布 Apple Silicon 与 Intel 两个包；Windows 继续使用 v1.0.3。

## 行为

- 正常查询只读取额度；收到 401 认证拒绝后，调用 Codex 的 `account/read`（`refreshToken: true`），再读取一次额度。每次采集最多执行一次强制凭据恢复，不因网络错误或 403 权限不足刷新凭据。
- Codex 负责凭据读取、刷新与存储，本工具不直接操作认证文件，不发送模型请求或兑换重置卡。
- 刷新凭据不可用、账号为空或重试仍被拒绝时，提示在 Codex 中重新登录。网络、超时、权限和版本兼容问题使用各自的提示，不保存服务器原始错误内容。
- “设置 → 数据与更新”保留采集器的具体错误。失败继续显示旧额度与原成功时间；成功后替换快照并清除错误。
- 单次采集等待上限为 35 秒，宿主的兜底终止为 45 秒；自动查询频率不变，不新增常驻进程。

长期未使用不必然导致故障：刷新凭据仍有效时，Codex 自身可能自动恢复。本版处理的是未自动恢复的认证拒绝路径，不把所有同步失败归因于登录过期。

## 验证方法与边界

协议回归覆盖正常成功、401 恢复、重试上限、刷新凭据失效、网络与权限失败、旧版 CLI、账号为空、乱序和重复响应，以及宿主保留错误与手动重试恢复。使用生产协议实现和隔离缓存，不读取真实账号。

联测使用 Codex CLI 0.142.5、虚构凭据、临时 `CODEX_HOME` 和本地 HTTP 服务。分别执行 arm64 与 x86_64 采集器，覆盖正常凭据、访问凭据失效、刷新凭据撤销、恢复后仍被拒绝、服务不可用、30 天未使用六种场景。

Intel 二进制在 Apple Silicon 的 Rosetta 环境执行，调用本机 arm64 Codex CLI；不是实体 Intel 硬件及 Intel CLI 的端到端验收。故障用户现场版本和认证状态尚未取得，因此不保证其问题一定与模拟场景相同。系统通知冷启动、完整拔屏 / Spaces / 休眠和干净设备首次下载未在本版重新验收。

本地全量回归共 418 项，363 项通过、55 项按平台跳过；额度专项 12 项通过。修订号调整后的发行工具测试 12 项通过。最终安装包的逐文件校验、源码一致性与运行时检查记录随 Release 提供。

## 构建与安装

App 基础版本为 1.0.3，构建号为 104；“关于”及发行标签显示 1.0.3.post2，最低构建目标 macOS 11。ZIP 中 `BUILD-INFO.json` 记录编译提交及源码摘要。固定源码标签为 `v1.0.3.post2`；独立安装助手在两个 ZIP 定稿后固定 SHA-256，因此包内源码的安装助手可能仍指向旧版，安装本版请使用 Release 独立的 `install.sh`。

发布使用现有 ad hoc 签名，未经过 Apple 公证。完整退出旧版后替换 App，保留用户支持目录即可继续使用原有数据。若升级后显示“登录已失效”，在 Codex 中重新登录，再点击“重试账号额度”。
