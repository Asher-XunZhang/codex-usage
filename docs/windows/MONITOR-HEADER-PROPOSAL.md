# 浮窗监控动态摘要设计

[任务监控](TASK-MONITOR.md) · [界面设计](LAYOUT-PROPOSAL.md) · [验证范围](VALIDATION.md)

监控顶部回答“所选任务现在最需要关注什么”，并提供独立的未读入口；不沿用其他页面的预算名称、百分比或 Token 数字。用量、预算两页继续使用电池式额度条。

## 信息层级

- 左侧以不同形状的状态符号、短句和柔和底色表达重点状态。
- 次行明确统计范围为全部已选监控，不受圆环/侧签的单任务常驻关注影响。
- 右侧显示未读消息数量，点击进入消息列表；打开列表不标读、不取消监控。
- 未知或部分来源不显示虚假的零任务或健康状态；可靠保存的未读信息可以继续显示。

状态优先考虑可靠的需处理事件、未知来源或存储问题，再表达执行中、等待新轮次和已结束。来源能力不足时不能显示已确认等待处理。活动订阅数、结束结果数和未读消息数分别计算，不使用任务结束数量绘制百分比。

## 状态连续性

切入监控页时，紧凑额度内容随紧凑形态退出，完整展开后只显示监控摘要。快照更新不重启展开动画，也不切换用户正在查看的其他页面。

顶部入口与主面板采用同一份最新监控快照，防止全部已读后仍按旧快照进入空未读列表。进入消息列表会退出旧详情并清除不相关搜索；单条消息的标读只由明确操作触发。

## 检查反馈

“检查任务”检查本地日志，不伪装成网络连接检查。操作中显示状态并阻止重复排队，完成后保留时间和结果。

结果同时考虑命令成功、来源健康和存储错误。普通轮询不能清除人工检查反馈；更换目录后拒绝旧目录的迟到回包，新来源故障优先于旧成功。目录发现、文件监听与单文件读取各自持有恢复条件，不能由无关轮询抹掉错误。

## 设计参考

[Notchi](https://github.com/sk-ruban/notchi) 的状态摘要与 [Notchcode](https://github.com/billxby/notchcode) 的常驻多任务入口提供了参考。[Windows 设计指南](https://learn.microsoft.com/en-us/windows/apps/design/guidelines-overview)与 [Widget 原则](https://learn.microsoft.com/en-us/windows/apps/design/widgets/)支持一眼可读、平静和可预期的呈现。

这里只借鉴信息层级与交互原则，不宣称这些项目的运行质量或功耗已被测试。当前来源限制见[任务监控能力说明](TASK-MONITOR.md#能力与限制)。
