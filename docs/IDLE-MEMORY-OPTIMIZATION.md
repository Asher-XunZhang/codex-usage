# 闲置内存与刷新设置：候选验证记录

基线为公开 v1.0.0（`53c9cf4`）。本记录包含合成组件实验、脱敏解锁实机观察及验证汇总，不包含个人用量、账号、任务记录或原始进程日志。

候选已完成安装、解锁实机采样及下述原生界面操作检查；最终菜单栏可见性与真实指针悬停也已由用户确认。离屏实验与完整应用观察分开呈现，当前数据不支持稳定的闲置内存收益；编辑操作后的暖态增长另见下文。

## 改动与使用取舍

- 明确隐藏浮窗时关闭并释放窗口及绘制视图；重新显示时保留位置、主题、置顶、独立筛选和摘要。悬停收起和主题切换仍使用同一窗口，避免以重建换取低读数。
- 相同的显示值不重复触发绘制通知。模型/任务选择器的文件和 JSON 中间对象在局部 autoreleasepool 内完成转换，再进入菜单回调；完整选项与取消逻辑保留。
- 手动刷新反馈替换上一条反馈，避免隐藏状态文案无限追加。
- 菜单栏和浮窗直接使用按需原生输入框设置自定义间隔，不启动主面板；原框错误提示、Return、Escape、重复打开和结束后的控件释放均有覆盖。
- 暂停后恢复上次正间隔。跨进程设置携带变更编号，后端设置携带递增版本，防止旧失败回滚或迟到 HTTP 请求覆盖新选择。
- 保留回收路径的交互门禁、合并和两秒最短间隔；没有周期性回收任务。输入、菜单、拖动、展开、动画和采集忙碌时跳过分配器请求。

没有改用 WebView、重启常驻宿主、减慢 hover 响应、减少筛选选项或清空统计索引来降低读数。主面板与常驻宿主的独立进程设计保留。

## 未采用的方案

字体和段落样式缓存的离屏实验虽减少重复构造，但最终占用中位数为 13.95→14.20 MiB，未显示内存改善，因此没有加入额外强引用缓存。

早期候选 C1 在每次收起后额外请求分配器回收。三轮交错实验中，冷收起与 50 次展开/主题循环后的中位数均与基线一致；所有回收调用返回 0 字节。因此最终候选 C2 撤销了这个高频触发点，只保留明确生命周期终点及已有回收路径的保护。

## 最终候选 C2 的离屏实验

环境为 Apple Silicon / macOS 26.5。使用相同优化构建参数，按 A1、B1、A2、B2、A3、B3 运行真实 AppKit 绘制与控制器方法；固定合成数据，每次使用独立偏好域和支持目录。执行 50 次展开/主题循环及 3 次原生动画，在动画后等待 5.2 秒，再执行隐藏和仅状态栏路径。

下面为各阶段三次 `ri_phys_footprint` 的中位数，单位 MiB：

| 阶段 | 基线 A | 最终候选 B |
| --- | ---: | ---: |
| 冷收起组件 | 9.7205 | 9.8300 |
| 50 次展开/主题循环后收起 | 13.2988 | 12.8925 |
| 动画后等待 5.2 秒 | 13.0959 | 13.1896 |
| 明确隐藏并等待 | 13.0646 | 13.1428 |
| 随后仅状态栏并等待 | 13.0021 | 13.1428 |

基线在普通隐藏后仍持有 panel/surface，候选均已释放；双方在明确的仅状态栏操作后都已释放。菜单对象没有残留。上述离屏实验记录的分配器回收请求均返回 0 字节。

这些结果**不支持稳定的闲置内存节省**，也不能把对象已释放等同于进程 footprint 立即下降。最终阶段候选反而高约 0.14 MiB；现有重复次数不足以区分稳定差异与分配器、绘图波动。保留这些改动的依据是更完整的生命周期管理、减少无效更新及功能可靠性，而非已证明显著减少常驻内存。

实验禁止可见窗口排序，没有启动应用启动回调、IPC、真实日志采集和额度查询；仅使用 bitmap 离屏绘制及非阻塞菜单替身。它不覆盖真实状态栏、WindowServer 可见窗口 backing、系统菜单渲染、真实输入缓存或像素一致性。六次运行均正常退出，绘图和屏幕断言通过，stderr 为空；这仍不是完整应用低于 10 MiB 的证据。

## 解锁状态下的真实应用观察

环境为同一台 Apple Silicon Mac、macOS 26.5（25F71）。基线 A 为 arm64 构建，候选 B 为包含 arm64/x86_64 的 Universal 构建，本轮均在 arm64 下运行，不能据此视为实体 Intel 验证。下表已纳入的轮次采样 130 秒，首尾均为浅色主题、60 秒自动刷新；同一轮先观察可见收起浮窗，再普通隐藏浮窗后观察菜单栏。实际样本间隔约 0.21 秒，并非严格固定为请求的 0.2 秒。

下表来自完整应用进程采样，指标为 `ri_phys_footprint / 2^20`，单位 MiB。Host-only 中位数仅使用当轮没有其他相关进程且数据完整的样本，不证明宿主正在闲置。合计包含观察到的宿主、统计和额度等相关进程；峰值是采样中观察到的合计峰值，不是完整生命周期峰值。此表与上面的离屏组件表分别解释，不合并计算。

| 场景 | 轮次 | 样本数 | Host-only 中位数 | 合计中位数 | 合计观察峰值 | 采样检查与条件 |
| --- | --- | ---: | ---: | ---: | ---: | --- |
| 收起浮窗 | A1 | 626 | 18.52 | 18.52 | 79.88 | 通过 |
| 普通隐藏后菜单栏 | A1 | 617 | 26.11 | 26.11 | 111.27 | 通过，但操作路径不等价，见下文 |
| 收起浮窗 | B1 | 619 | 23.27 | 23.27 | 84.35 | 通过 |
| 普通隐藏后菜单栏 | B1 | 619 | 23.21 | 23.21 | 85.43 | 通过 |
| 收起浮窗 | A3 | 625 | 23.42 | 23.42 | 108.98 | 通过 |
| 普通隐藏后菜单栏 | A3 | 623 | 23.47 | 23.47 | 109.46 | 通过 |
| 收起浮窗 | B2 | 625 | 18.71 | 18.71 | 79.91 | 通过 |
| 普通隐藏后菜单栏 | B2 | 625 | 19.06 | 19.06 | 105.46 | 通过 |

A1 菜单栏轮次前有一次超时的 `⌘3` 操作，可能已经打开过状态菜单，因此可能存在额外菜单操作及系统缓存差异。虽然采样器返回 `valid=true`，也不能把这一轮视为与候选完全等价的对照，或把读数差异归因于修改。A1 收起浮窗的宿主占用也存在轮内变化，首个样本为 23.21 MiB，最后一个为 18.50 MiB。

A2 收起浮窗轮次已排除：采样首尾主题由浅色变为深色，采样器返回 `valid=false`，用户确认曾手动切换主题。该轮采样内未观察到主面板 GUI；采样后出现主面板的事实不用于推断其在采样期间已打开。更早另有一组 130 秒采样在结束后的首次界面操作发现 Mac 已锁屏，锁屏时点不明；即使其进程检查为 `valid=true`，也已排除出解锁状态对照。

这些实机数据是明确操作条件下的有限观察，**未验证出稳定的闲置内存收益，也不足以据此判断稳定回归**。基线和候选自身的不同轮次均有变化，不计算优化百分比。真实 Codex 日志会随实验工作增长；暖机历史、系统图形缓存和短时相关进程也可能不同，不能将它们视为固定数据集下严格匹配的重复实验。进程枚举与资源读取并非原子操作，短于采样间隔的进程和峰值可能漏记；WindowServer 等共享系统服务不计入应用合计，CPU 与能耗未在本轮报告。

## 原生界面与进程检查

- 浮窗直接打开原生输入框，验证 0、3601、非数字的原框提示与输入保留；单独的 Return 应用、Escape 取消及取消按钮正常。取消后仍为原间隔；应用 17 秒后，不启动主面板及其 Python 服务。
- 重复打开时聚焦同一输入框并保留文本由原生控件测试覆盖。实机自动化对状态菜单的跨调用读取存在失效与延迟，没有把 AX 返回成功或原框仍显示本身当作重复打开动作已经完成。
- 浮窗菜单暂停后仍可手动刷新；恢复菜单显示并恢复 17 秒。状态栏菜单暂停、应用退出及重新启动后，暂停状态和记忆的 17 秒均保留。
- 主面板原生自定义框读取同一记忆间隔。设为 23 秒后，主面板、浮窗和真实后端 `/health` 一致；随后连续选择 30、60 秒，最终界面和后端均为 60 秒。请求乱序、失败补偿和 ABA 另由自动化测试覆盖，不以这一次实机操作替代并发测试。
- 浮窗独立选择 7 天、模型和任务，主面板范围保持今天。普通隐藏再显示后，位置、主题、置顶和双方的筛选逐项一致。主面板及宿主 PID 未随浮窗开关而变化。
- 主面板关闭按钮及隐藏命令分别检查，浮窗继续存在，宿主 PID 不变；主面板及其统计服务退出。应用整体退出后没有遗留本应用进程。
- 深色/浅色切换及重新显示的真实窗口已检查。最终安装后，用户确认菜单栏图标可见，真实鼠标移入展开、移开收起及时正常；自动化工具不能完整代替这两项观察。

## 原生编辑后的暖态成本

在同一宿主进程、浅色收起浮窗、自动刷新暂停的条件下，每个观察窗口为 30 秒。额度查询仍可能出现，因此同时报告观察到的合计峰值。下面是操作后的观察，不是与旧版自定义输入路径的对照：

| 阶段 | 样本数 | Host-only 中位数 MiB | 合计观察峰值 MiB |
| --- | ---: | ---: | ---: |
| 一次无效输入并取消后 | 145 | 26.33 | 87.55 |
| 再进行五次编辑/取消后 | 146 | 35.89 | 97.04 |
| 后续五次固定 AX 设置文本、点击应用/取消后 | 145 | 36.50 | 97.85 |

前两段之间有键盘、焦点或输入法干扰，后续固定按钮组之前也有受打断的尝试，因此不能按表格计算每次操作的泄漏量。最后五次固定按钮循环全部完成，校验提示和取消均正常。

后两次 heap 检查均未识别出存活的 RefreshIntervalPrompt、RefreshIntervalPanel、NSTextField 或 NSTextView/field-editor；NSPanel 和 CapsuleSurface/Host/State 各为一个，符合仍显示的浮窗。三个 NSTextFieldCell，以及输入法、候选词、拼写检查、补全等已识别对象的数量也没有增加。这支持本次窗口与控件释放路径有效，不代表所有内存都已返还给系统。

两次 heap 的 malloc 已分配量仍增加约 1.05 MiB，包含约 730 KiB 未分类分配、192 KiB Metal ResourceList 等；没有分配调用栈，不能确认这些增长都属于缓存，也不能据此证明长期有界。原生文本输入会加载系统组件，实际使用后的暖态成本应纳入产品取舍。保留此入口是为了避免仅修改间隔就打开整个主面板及其统计服务，并提供标准键盘编辑体验；不宣称该功能没有额外常驻成本。
