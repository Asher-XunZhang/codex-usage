# 数据可信与状态完整

让用户始终知道正在看什么、修改什么以及哪些操作已经生效。状态正确性覆盖等待、失败和恢复，不止成功路径。

## 数据含义与一致性

- 区分数据来源、范围、时间与可信程度。未知、过期、不完整和真实零值分别表达；独立来源的结果和错误也应独立呈现。
- 从业务定义确定计算口径，再实现显示与聚合。本地使用量、账号剩余额度和估算费用有不同含义，不因能画在同一界面就相互推断或混算。
- 把筛选条件和返回结果视为一个快照。异步结果只有仍属于当前请求与数据源时才能发布；失败时可以保留有明确标识的旧结果，不能让新条件看似对应旧数据。
- 搜索、排序和导出明确作用范围。导出或后续操作使用经过确认的一致快照，避免用户看到的范围与实际处理范围悄悄分离。

## 状态所有权与编辑

- 为共享状态指定权威来源；窗口与控件消费状态，避免各自维护相互矛盾的副本。同步时区分对象身份、内容版本和操作意图。
- 用户草稿独立于后台刷新的已保存数据。导航、切换对象、异步加载和保存回包均不应静默丢失较新的编辑。
- 区分请求已发出、写入已成功和后续界面动作已成功。反馈依据真实完成边界；失败后用户能知道哪些内容已生效，重试不会重复造成副作用。
- 配置与持久化变更应可迁移、可恢复。损坏数据保留诊断或恢复依据，不以静默清空掩盖问题。

## 恢复与验证

- 错误说明影响和下一步，保留继续工作的上下文；缺少依赖、无效输入与暂时不可用应有各自适合的恢复入口。
- 对异步修改，至少考虑顺序反转、重复触发、执行中切换上下文、失败后重试中的相关情况。取消或关闭不能让迟到结果重新改变已失效的界面。
- 用能推翻错误实现的场景验证不变量；时间边界、单位精度和跨实现一致性根据涉及的业务选择，不为每个改动固定运行所有边界组合。

修改具体统计或预算规则前，从 [文档导航](../../../docs/README.md)选择适用平台的说明，再核对对应实现与测试。[macOS 预算定义](../../../docs/macos/BUDGETS.md)记录基线规则，两端差异由 [对齐清单](../../../docs/common/WINDOWS-MACOS-ALIGNMENT.md)说明。技能规定判断方法，业务口径和周期规则由这些维护中的来源承载。
