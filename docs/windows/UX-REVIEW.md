# Windows 交互审查要点

[界面设计](LAYOUT-PROPOSAL.md) · [预算管理](BUDGETS.md) · [任务监控](TASK-MONITOR.md) · [验证范围](VALIDATION.md)

本页记录可复用的审查原则和当前验证边界。界面中的每个操作应说明对象、范围、完成条件和恢复入口；不能只靠改文案掩盖行为冲突。

## 动作与分组

- 关闭主面板、收起浮窗、隐藏至托盘和退出应用分别表达对象。切换常驻方式不隐式关闭已有主面板。
- 保持展开与窗口置顶独立；主动收起优先，不立即被悬停重新展开。
- 查看、编辑靠近当前对象；暂停/恢复靠近提醒状态；删除单独分隔并确认。
- 高频操作留在当前界面，低频外观和窗口行为进入分组菜单。浮窗快捷取消与清理只影响指定订阅或结束结果。
- 全局设置在每个主页面都可访问，托盘独立运行时也能修改外观。

## 数据与异步反馈

- 筛选和结果作为同一快照，失败时不能在新筛选旁放无标记的旧值。
- 搜索范围与导出范围明确，默认导出与可见结果一致。
- 本地日志、账号额度和任务监控分别标记时间与错误，不使用含义混杂的“刷新成功”。
- 编辑草稿按对象保存，重试和切换不会丢失更新内容。提交成功与后续窗口动作成功分开判断。
- 预算缺价、窗口无效、覆盖不足与文件损坏提供具体恢复入口。未知不当作零或已耗尽。
- 未读消息、执行状态和订阅状态独立，读取提示不等于处理完毕。

## 命中与连续性

文字、背景和点击区域应同步移动，动画不临时制造第二个圆环或残留上一页内容。拖动越过阈值后不再执行原按钮，松手、捕获丢失、隐藏和异步保存有明确所有权。

键盘顺序与阅读顺序一致，Tab 和读屏可逐项操作。鼠标被动焦点返回不生成键盘框；迟到的菜单恢复不能覆盖新的输入意图。透明区域穿透，不通过扩大工具提示范围解决信息不足。

检查浅深主题、窄窗口、长名称、数字列对齐、不同缩放与过渡中间帧。省略文字需要完整查看入口，不能遮挡旁边按钮或只让字体变小。

## 仍需保持公开的限制

真实系统通知可见性、点击和冷启动回调尚无稳定端到端证据；自动恢复所属窗口焦点也存在未稳定通过的测试边界。当前日志没有可靠等待审批和失败事件来源。混合 DPI 硬件、第三方窗口组合及 macOS 原生运行需要各自实机验证。

这些限制应与功能说明一起维护；不能将原生注入、离屏绘制或接口提交等同于所有真实桌面行为已通过。具体方式见[验证范围](VALIDATION.md)。
