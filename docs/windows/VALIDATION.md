# Windows 验证范围

[Windows 使用说明](README.md) · [任务监控](TASK-MONITOR.md) · [预算管理](BUDGETS.md)

发布结果须对应同一份源码、构建清单与发行包，历史通过记录不能替代当前发布工作流。Windows v1.0.3 与 macOS 同版本发行，但本轮不替换既有 macOS 资产；共享代码的 CI 验证与已发布 macOS 包的验收记录分别说明。

本页目前记录源码阶段的验证范围与限制。最终发行包的通过结果须在构建、打包和验包完成后单独记录，不能从下面的测试入口推定已经通过。

## 证据分类

| 类型 | 覆盖内容 | 不代表什么 |
| --- | --- | --- |
| 自动单元与回归 | 统计、预算、生命周期、持久化、恢复及包边界 | 不证明桌面显示或通知一定可见 |
| 离屏 WPF 绘制 | 主题、长文案、边界、对齐、DPI 与形变帧 | 不等于实际鼠标操作或显示器帧率 |
| 原生窗口与注入坐标 | 生产手势、真实捕获、菜单、拖动、贴边、键盘和 UIA | 不等于全部硬件和第三方窗口组合 |
| 隔离进程 IPC | 实际进程、刷新、订阅、消息路由、去重与清理 | 不证明系统横幅和通知中心点击 |
| 实际桌面操作 | 曾检查任务选择、预算编辑、菜单、消息及对应详情 | 只证明当时构建与环境，不能代替最终发行验收 |

## 回归入口

完整命令见[构建与验证](README.md#构建与验证)。测试使用合成日志和隔离配置，不要求真实账号。遗漏 `CODEX_USAGE_WINDOWS_EXE` 而跳过的 Windows 检查不能计为通过；随包 Python 与后端必须来自同一构建。

以下参数传给 `CodexUsage.exe`，配合 `--output <报告路径>` 保存结果。读取报告前须等待 GUI 程序退出；PowerShell 可使用 `Start-Process -Wait`。

| 参数 | 范围 |
| --- | --- |
| `--monitor-tests` | 监控、存储、通知策略与顶部模型 |
| `--monitor-ui-tests` | 选择、取消、已读、身份、消息路由与恢复 |
| `--monitor-floating-tests` | 多状态、多档缩放渲染 |
| `--arc-editor-tests` | 配色草稿、无效 HEX、主题、UIA、保存失败重试与取消撤销 |
| `--quota-toggle-tests` | 隔离 Host 的额度开关、持久化、写入失败与启动覆盖 |
| `--main-push-tests` | 宿主状态版本、预算选项独立来源身份与迟到结果 |
| `--worker-tests` | 有界事件协议、刷新票据、崩溃恢复、空闲无状态回调与进程释放 |
| `--reliability-tests` | 异步读取、草稿、配置损坏、关闭失败和辅助操作 |
| `--layout-tests` | 主面板、预算、设置和托盘布局 |
| `--capsule-drag-tests` | 整框拖动、防误触、捕获丢失及保存交错 |
| `--capsule-drop-tests` | 圆环抓取、展开中接管、越界回位与展开方向 |
| `--capsule-departure-tests` | 过渡区域后无鼠标事件时仍正确收起 |
| `--dock-tests` / `--hover-tests` / `--morph-tests` | 贴边、悬停与形变 |
| `--capsule-keyboard-tests` | 键盘入口与菜单返回时序 |
| `--preview-controls` | 原生 Popup、下拉列表和菜单 |

几何测试使用负坐标、相邻或错位屏幕及不同 DPI 的合成矩形。交互诊断使用真实 WPF 捕获、通过生产 Pointer 入口注入坐标，不移动真实鼠标、不把私人任务当作夹具。

## 发布包检查

验证器校验文件清单、SHA-256、x64 PE 架构、运行时隔离和源码边界，并在含中文与空格的路径下解包测试。程序、后端、Python 和许可须来自同一候选，源码变化后须重新构建。

`--background` 避免前台激活和部分弹出层检查，报告标记跳过项，不能冒充完整前台验收。`--skip-smoke` 仅检查结构和校验和。工作流见 [Windows 检查配置](../../.github/workflows/windows.yml)。

## 当前限制

- 通知 XML、转义、稳定标签、后台已读参数、应用路由和 API 提交有检查；真实横幅与通知中心的可见性、点击，以及冷启动激活尚未完成可靠端到端验收。API 提交成功不能写成用户已收到，应用内消息可独立核查。
- 自动返回所属窗口焦点的检查曾不稳定。显式激活后的画面与键盘检查不能代替自动焦点返回，未稳定通过的部分不计为完整通过。
- 未覆盖全部混合 DPI 实体显示器、输入设备、第三方叠加层或通知策略，合成几何不能替代硬件实测。
- Windows 环境不能运行 AppKit / Swift 回归。共享后端静态核对或 Windows 测试通过，不表示 macOS 新构建已完成实机验收。
- 当前日志不提供可靠等待审批与执行失败事件。日志安静、断线、用量不增长和子任务结束不被判为主任务完成。

## 性能与资源

Windows 父进程监测同时等待进程句柄和停止事件，退出或取消时唤醒。这只消除了该线程的周期超时，不表示所有计时器均已消失；macOS 节奏独立维护。

资源比较使用 `python -B -m tools.windows.measure_resources`，浮窗可用 `--capsule-benchmark` 采样。Windows 工作集不直接与 macOS physical footprint 比较，渲染回调间隔也不是实际帧率。短时样本不用于承诺固定内存、功耗收益或所有机器上的流畅程度。
