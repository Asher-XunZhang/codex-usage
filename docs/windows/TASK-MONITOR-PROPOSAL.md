# Windows 任务监控设计与状态约定

[用户操作](TASK-MONITOR.md) · [动态摘要](MONITOR-HEADER-PROPOSAL.md) · [验证范围](VALIDATION.md)

监控是本工具对明确任务轮次的观察与提醒。它不向 Codex 发送控制命令，不将本轮结束解读为需求完成，也不将用量筛选当作监控选择。

## 三类独立状态

| 状态 | 归属 | 不应混同 |
| --- | --- | --- |
| 执行状态 | 当前任务和轮次 | 结束不等于需求完成；未知不等于失败 |
| 订阅状态 | 本工具的仅本轮或每轮提醒 | 取消订阅不停止 Codex；每轮订阅在两轮间仍有效 |
| 消息状态 | 逐轮事件与是否已读 | 已读不表示已处理，也不抹掉结束结果 |

默认不自动监控全部任务。选择保存时核对任务身份、父子关系和轮次；同名任务以项目和开始时间区分。并发保存或任务恰好结束时，保留逐项结果，不将旧轮次静默替换为新轮次。

## 来源与能力

当前实现通过本机日志明确的生命周期事件判断开始、结束和中断。等待审批与执行失败没有可靠来源，提醒选项按能力禁用；未来来源支持后才可启用，界面预留图形不等于已取得数据。

任务日志安静、Token 不增长、断线和子任务结束均不能推断主任务完成。刚开始且没有用量的任务也需要发现；长期运行任务的开始事件可能不在尾部，因此读取采用有预算的分段回溯和持久化检查点。未找到可靠边界前保留待确认。

读取需要处理半行、截断、归档、文件移动与重启。新事件优先于历史续扫，普通轮询不能无条件清空发现或监听错误。不可读日志保留上次确认状态及来源说明，不替换成演示数据。

## 顺序与持久化

监控轮询、取消、已读、设置和通知提交共享顺序，避免取消后产生迟到提醒。订阅与消息先可靠保存，再决定通知；写入失败时不假装已生效，也不继续发送可能重复的事件。

事件以任务、轮次和终结事件去重；重启恢复有效订阅，离线结束补入记录而不逐条补弹。仅本轮订阅不会串到下一轮。每轮订阅在终结后保持有效并等待新一轮。

清除已结束结果仅删除非活动订阅，保留活动监控和消息；清理已读历史保留未读及仍需处理的记录。存储损坏时禁止将其当成正常空列表，保留原文件并提供明确备份恢复。

## 多窗口与提醒

后台宿主是共享监控状态的所有者。主面板、浮窗、托盘和通知消费同一状态；关闭主面板不停止监控，关闭本工具才结束观察。取消、清理和已读都必须按真实任务或消息标识路由。

圆环和侧签保留额度主体，任务用独立静态符号表示；不自动展开、不移动或抢占前台、不用持续闪烁表达未读。浮窗顶部汇总全部已选任务，常驻关注只控制紧凑形态的重点任务。

通知偏好包括系统通知加标记、仅标记、声音、隐藏名称和暂停。全屏或暂停时继续记录；恢复不补弹旧消息。通知参数不能包含提示词、回复正文或文件内容。系统 API 提交、系统呈现和用户点击是不同完成边界，真实呈现与点击限制见[验证范围](VALIDATION.md)。

## 检查与导航

检查操作即时反馈，保留成功时间、部分可用或失败原因；命令返回成功不代表所有来源健康。普通状态更新不能覆盖明确检查反馈，更换目录后拒绝旧回包。

未读入口直接打开消息列表；任务详情、消息详情和列表路由分开，不借用伪造任务 ID。列表进入时使用最新快照选择未读或全部历史并清除旧搜索。仅打开列表不标读，打开单条消息只标读该条。

详情可以复制标识，但当前没有已验证的 Codex 原任务定位接口，不提供只打开客户端首页却声称定位任务的按钮。

## 验证重点

验证应覆盖选择与结束竞争、取消与通知排队、半行及长轮次回溯、截断和重启、持久化失败、来源恢复、未读与需处理独立、暂停不补弹，以及源快照与列表过滤的一致性。几何与离屏渲染补充长名称、多主题、多缩放和形变边界，不能代替真实通知或硬件验收。
