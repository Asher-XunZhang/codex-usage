## 收起态和贴边态设计修订（按用户澄清纠正范围）

用户随后明确：需要改善的是**新增监控在收起／吸附形态中的呈现**，截图特别标出了监控三角形；并非重做额度圆环。先前将圆环整体改为 136×44 横向胶囊、四边均改为 60×32 横签的理解有误，已撤回。此前 `compact-motion-final.mp4` 仅是该错误方向的中间预览，不能作为最终设计或验收依据。

当前保留原 **76×76 pt 额度圆环**和额度色阶。监控借鉴 Windows 将执行状态、关注范围、未读数和额度分开的语义；环内底部使用独立小状态区，不压住额度弧线。执行中为静态省略号、本轮结束为勾、中断为方块、未知为问号、等待下一轮为时钟；未读数在同一区域另列，超过 99 显示 99+。没有订阅和未读时保留原范围文字。执行状态不表示进度，图形不是播放或停止按钮；展开后有完整中文状态与操作。

左右边为 **36×76 pt 竖签**，上下边为 **80×32 pt 横签**。数字始终正向可读，监控标记拥有独立位置。离开后 550 ms 隐藏、进入可见侧签 120 ms 恢复圆环、真实移动后才展开的行为保持。收起／展开和侧签转换使用分阶段淡入淡出，避免两份百分比叠在一起；减少动态效果时直接到达目标。无常驻闪烁、旋转或新的指针轮询。

修正动画见 [原生绘制演示](screenshots/monitor-ring-correction.mp4)，使用演示数据和可控时序，不是安装版录屏。它覆盖运行、结束并产生未读、来源异常三种监控状态，额度均保持 50%，用于检查两种信息不会互相冒充。最终桌面验收仍单独记录。

当前 Apple [Live Activities 设计指南](https://developer.apple.com/design/human-interface-guidelines/live-activities)支持紧凑、最小和展开形态按信息优先级取舍；这里借鉴信息层次，未引入 ActivityKit 或提高 macOS 11 最低目标。Windows 的 `TaskMonitorGlyph`、`TaskMonitorHeaderDisplay` 和 `CapsuleEdgeIndicator` 已直接核对；只借鉴可验证的任务状态，不加入没有可靠事件来源的等待审批或失败推测。

状态／存储与 JSONL 读取共 19 项测试通过，独立宿主服务集成测试 1 项通过。集成测试使用真实 Swift 服务和隔离生成日志，验证初次发现、在线完成消息、保存及重启不补弹；不调用系统通知 API。导航测试已确认三页使用同一窗口，反复切换保留预算草稿与用量筛选，未启动后端或显示真实窗口。选择 sheet 是随后接入的界面，仍需复测与交互验收。首版监控及浮窗通过 arm64 候选构建，尚未替换安装；后续修改需要重新构建。

读取只接受明确生命周期事件，保留秒／毫秒时间兼容；晚到的旧轮次终止不能覆盖新轮次。大文件从尾部进入，再按调用者字节预算反向补查；测试包含跨初始尾部边界的生命周期、17 MB 对话行、半行追加、原文件替换、子代理继承记录和不同 JSON 字段顺序。检查点不保存原始行内容。

宿主共用已有目录事件流；原生监听丢失标志触发分批目录核对。活动订阅保留 60 秒、10 秒容差的兜底；事件输入合并使用短时可取消任务。已修正 `/var` 与 `/private/var` 同源别名导致漏读或误标离线的问题，归档移动沿用源读取器的在线状态。

消息列表按页跨进程传输，每页 30 项；操作回执和通知投递分开。通知先检查当前权限与最新暂停设置，并可靠保存“正在交给系统”后再提交；重启时未确认的投递只留消息。预算和任务通知通过一个类别注册与 delegate 路由，任务暂停不改变预算暂停。横幅和声音是否实际出现仍需安装版验收，专注模式不作绕过。

## 后续接入与回归边界

统一设置由宿主独占，嵌入原数据设置视图，不再另建数据设置窗口；原生 popover 只消费已有快照，其数字可选择复制。监控新增选择 sheet、现有策略切换、取消关注、双击任务详情、浮窗监控内容和唤醒补查。目录监听共用原事件流，普通 SQLite 文件变更不再无条件触发递归监控扫描。

后端通知仅在 macOS 显式启用：stdout 只承载版本化、每行最多 4096 字节的事件，普通日志走 stderr；服务端保留最新状态、有界合并，慢读取方不阻塞扫描。Swift 通过可读事件和单次 POSIX read 收取短消息，避免 Foundation 读取等待填满缓冲区。正常连接不保留 1 秒或 150 ms 完成轮询；断流时 5–60 秒退避，长扫描有单次 120 秒核对。主窗口关闭仍由已有父进程退出机制回收后端。

预算与事件通道相关 27 项曾有 1 项旧额度窗口测试失败（未提供账号快照）；补充真实窗口样本后，预算 UI／核心、监控核心、原生三页导航组合 36 项通过。之后仍有监控显示与圆环范围纠正，完整回归及最终构建进行中，不能将此次数当作最终全量通过。

## 圆环到面板的连续形变（后续用户反馈）

对照当前 Windows `CapsuleMorph.cs`：一个可逆进度同时驱动轮廓、圆角与内容。前 12% 淡出圆弧及附属文字，14% 起改变轮廓，76% 完成宽度、84% 完成高度，86% 起淡入详情。macOS 按同一顺序修正原来的圆环／摘要二段淡入淡出：保留一个百分比字形，连续移至原有额度摘要位置；文字完整边界受圆角安全区约束，不靠裁切展示半个数字。字体保持两个固定字号并缩放，避免逐帧创建字体。展开 280 ms、收起 220 ms，中途反向按剩余距离缩短时长；减少动态效果仍直接切换终态。

macOS 使用单个 NSPanel 的原生 frame 更新，Windows 使用预留 HWND 内的自绘范围；实现方式遵循已批准的平台方案。最终圆环、额度摘要、监控内容布局保持当前 macOS 语义。本次是形变对齐，不将 Windows 的监控标题布局一并替换进来。

[正常速度及四分之一速度原生动画](screenshots/morph-continuous.mp4)为演示数据，不是桌面录屏。几何测试覆盖四个展开方向、4,004 个进度点、反向一致性及 1,000 个分数坐标圆形文字安全区；原生 Surface／Host／控制器相关 21 项通过。实际安装记录以[验收页](FEATURE-SYNC-VALIDATION.md)为准。

## 系统通知定位对应消息

点击任务通知向主窗口传递有界消息 ID 集合，历史页只展示本次通知关联消息，并提供“返回全部历史”。无效或已清理的消息显示空状态，不回退成其他任务；打开列表不自动标读，“本通知全部标为已读”只处理关联 ID。不同消息范围的迟到快照被拒绝。跨窗口路由使用独立 routeID 与递增序号，旧回执不能清除新跳转，重复／迟到的跳转不重新重置页面。新增旧消息晚到反例先失败后通过，通知动作、页面范围及路由顺序的最终 3 项专项通过（7.297 秒）。

通知后台“标为已读／暂停”在宿主存储回执后才调用系统完成回调；没有宿主或未知动作也结束回调，不卡住系统通知处理。通知边界与原生消息筛选 3 项测试通过（21.782 秒），包括只读打开、关联范围、失败回执及返回全部历史；未将这些替身／离屏测试等同于系统横幅或冷启动点击的实机验收。
